# `review_workspace` — Non-Destructive Blind Human Review Storage Layout

This workspace holds local runtime state generated by `src/review_dashboard` when human reviewers annotate [`blind_annotation_workqueue.csv`](../blind_annotation_workqueue.csv).

- `review_dashboard.sqlite3`: Transactional SQLite WAL store (isolated `reviewer_annotations`, `submission_history`, `adjudications`, `audit_log`).
- `submissions/reviewer_a/*.json` & `submissions/reviewer_b/*.json`: Atomic immutable JSON snapshots written on reviewer submission.
- `adjudications/*.json`: Post-submission adjudication resolution records (unlocked only after both Reviewer A and Reviewer B submit).
- `snapshots/{reviewer_a,reviewer_b}/`: Optional reviewer-captured keyframe PNG/JPG extracts.
- `exports/`: Exported `annotations_reviewer_a.jsonl`, `annotations_reviewer_b.jsonl`, `adjudicated_annotations.jsonl`, `blind_annotation_workqueue_populated.csv`, `agreement_report.json`, and `release_metadata_snapshot.json` (validated against `../schema.json`).
- `backups/`: Consistent SQLite snapshots via `sqlite3.Connection.backup()`.
- `.proxy_cache/`: Ephemeral LRU-bounded (`max_proxy_pairs=2`) 720p H.264 browser fallback proxies if a browser cannot natively hardware-decode 4K HEVC back videos.

**Important:** Starting the dashboard or reviewing items here **never modifies** frozen `v1.0` (`dual_camera_gt_v1.0_ai_assisted_audited`), Stage J/K results, models, or the checked-in `PENDING_HUMAN_REVIEW` root manifest files until humans explicitly submit and export.
